MyJSON

A JSON and YAML workstation with no backend at all — there is simply nowhere for your data to go. Every feature had to be engineered to survive that constraint, including real jq.

The problem

Every developer has done it: paste a production payload into the first JSON formatter a search returns, then feel a small cold moment about what was in it. Auth tokens. Customer emails. An internal URL that shouldn't be in a stranger's request log.

Most online JSON tools POST your document to a server. The ones that don't are usually one narrow page — a formatter or a validator or a converter — so a real task means pasting the same sensitive blob into four different sites.

MyJSON took the opposite constraint as its starting point: the app is not allowed to make a network request while you work. Everything else followed from having to honour that.

The decisions that cost something

A privacy claim is cheap to write and expensive to keep. These are the places where keeping it actually made the engineering harder — which is the only real evidence that the constraint was honoured.

Decision 01

Make the promise verifiable, not trustworthy

"Trust us" is the weakest possible privacy claim. So the promise is stated as something a skeptical developer can check in ten seconds: open DevTools, watch the Network tab, and use the app. Nothing fires. A status-bar badge says so, and there is a dedicated page explaining exactly what that does and doesn't cover.

This forced a real cost — no server-side anything, ever, for any feature — but it turned the product's main claim into something falsifiable.

Decision 02

Ship real jq, not a jq-flavoured subset

The obvious path was to reimplement a useful subset of jq in TypeScript. Every such subset lies the moment a user pastes a filter from Stack Overflow that touches the part you didn't implement — and they can't tell whether the bug is theirs or yours.

Instead, MyJSON ships jq 1.8 itself, compiled to WebAssembly, running in the browser with a --raw-output toggle. Filters behave exactly as they do in a terminal, because it is the same jq. The cost is bundle weight and a lazy-loading strategy; the benefit is that the tool never quietly lies.

Decision 03

Three query languages, because people know different ones

JSONPath, jq, and RFC 6901 JSON Pointer sit side by side, all evaluating live as you type, with matched paths revealed back in the editor. They are not redundant: JSONPath is what most API docs use, jq is what pipelines use, and JSON Pointer is what JSON Patch and OpenAPI use. Forcing one on everyone would just be a preference dressed as a design.

Decision 04

Sharing, without a server to share through

Share links normally mean an upload and a database row. Here the document is LZ-compressed and embedded in the URL hash — the fragment never leaves the browser, so a shared link carries its own payload and still touches no server. It also means shared links can't be revoked or mined, which is the honest trade and is documented as such.

Decision 05

Degrade, don't die, on large documents

Monaco is a full IDE engine; on a multi-megabyte document its niceties become the reason the tab freezes. Above roughly 1 MB the editor deliberately scales its features down instead of trying to do everything and stalling. Heavy views are code-split, one parse result is shared across every view rather than re-parsed per panel, and editor re-renders are trimmed to what actually changed.

Decision 06

Redact before you share, not after you regret

One toolbar action masks JWTs, emails, UUIDs, IP addresses, credit-card numbers and credential-keyed values to <redacted:…>. Originals survive only in the in-memory undo stack — never written to disk, never persisted — so the safe version is the one that leaves the tab.

Don't take my word — test it

This little widget obeys the same rule as the product: open DevTools, watch the Network tab, and use it. Nothing fires. I kept it deliberately tiny — the real workstation adds Monaco, jq 1.8 in WebAssembly, seven formats and plenty more — but the rule it demonstrates is the one the whole product is built on, and you can check it right here.

What's in it

  • Editing. Monaco with 14 themes, JSON/YAML mode toggle with lossless conversion, JSON5 fallback so comments and trailing commas just work, format/minify, and drag-drop or paste up to 25 MB.
  • Inspection. Tree view with search highlighting and copy-subtree, a sticky cursor-path breadcrumb, table view with sorting, filtering and CSV export, and a search overlay across keys and values that auto-expands the tree.
  • Schema. Ajv-powered live validation, plus one-click schema inference from the current document with format detection for email, URI, UUID and date-time.
  • Diff. Three modes — Monaco side-by-side, structured (click a change to jump to it in the editor), and RFC 6902 JSON Patch.
  • Codegen. TypeScript, Zod, Go with json tags, Rust with serde, Python dataclass, Pydantic and JSON Schema.
  • Conversion. Bidirectional across JSON, YAML, XML, CSV, TOML, NDJSON and TOON, with a live token-savings estimate for the TOON target.
  • Decoders. JWT, Base64, URL, hex and Unicode, an NDJSON viewer, and secret-on-paste detection.
  • Keyboard-first. A fuzzy command palette on Ctrl+P plus direct shortcuts for format, minify, download, clear and search — the whole tool is usable without reaching for the mouse.
  • Accessibility and delivery. A full WCAG 2.2 AA pass — live regions, focus traps, keyboard navigation, contrast — and a hand-rolled service worker that keeps it fully usable offline as a PWA, with eleven focused landing pages for the tasks people actually search for.
Honest note

A handful of visual refinements are deliberately parked rather than shipped half-done — chiefly consolidating some repeated UI into shared primitives, and revisiting the dynamic root font-size, which interacts badly enough with rem-based utilities to deserve a considered fix rather than a patch. The correctness, accessibility, performance and SEO work is landed and verified.
